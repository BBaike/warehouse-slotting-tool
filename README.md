# warehouse-slotting-tool

Веб-инструмент для планирования размещения коробок на складе. Пользователь описывает склад и типы коробок, задаёт партию (сколько коробок какого типа нужно разместить), а приложение раскладывает коробки по этажам, строит 2D-схему и показывает процент заполнения и список того, что не поместилось.

Это MVP-макет для портфолио: цель — показать структурированный, типизированный и протестированный код, а не готовый продукт. Без сервера, авторизации, 3D и деплоя — всё работает локально в браузере.

## Что умеет

- **Склады** — создание, редактирование, удаление; несколько этажей, размеры пола, ширина проходов и глубина рядов.
- **Типы коробок** — размеры, вес, цвет для схемы, флаг «можно поворачивать на 90°».
- **Размещение** — партия (количество коробок каждого типа) на выбранном складе:
  - процент заполнения — общий и по этажам;
  - сколько коробок размещено и сколько не поместилось, с причиной («слишком высокая», «не влезает ни в одной ориентации», «нет места»);
  - 2D-схема этажа: ряды, проходы, коробки цветом типа, вкладки по этажам, подсказка при наведении.
- Все данные хранятся в `localStorage` браузера; повреждённые или устаревшие данные не роняют приложение, а откатываются к демо-набору.

## Как запустить

Требуется Node.js 18+.

```bash
npm install
npm run dev       # запуск в режиме разработки, http://localhost:5173
npm run build     # production-сборка в dist/
npm run preview   # локальный просмотр production-сборки
npm run test      # тесты (Vitest)
npm run lint      # ESLint
npm run typecheck # проверка типов (tsc)
npm run check     # typecheck + lint + test + build — полный набор проверок
```

## Стек

- Vite + React + TypeScript (strict)
- Vitest — тесты
- ESLint — линтинг
- SVG для 2D-схемы, без сторонних библиотек рендеринга/графиков
- Хранение состояния — `localStorage`, без бэкенда

## Алгоритм

Размещение коробок — двухшаговая задача:

1. **Разметка этажа** — ширина этажа режется на чередующиеся ряды и проходы (схема «ряд–проход–ряд» для двустороннего доступа, у стен — одиночные ряды). Остаток ширины, в который не влезает полный ряд с проходом, не используется.
2. **Упаковка ряда** — внутри каждого ряда коробки укладываются алгоритмом **MaxRects** (J. Jylänki, [«A Thousand Ways to Pack the Bin — A Practical Approach to Two-Dimensional Rectangle Bin Packing», 2010](https://github.com/juj/RectangleBinPack)): список максимальных свободных прямоугольников, вставка по эвристике (лучшая короткая/длинная сторона остатка или лучшая площадь), разрезание и чистка свободного пространства после каждой вставки.

Планировщик прогоняет комбинации сортировки партии и эвристик MaxRects (мультистарт) и выбирает результат с наибольшей размещённой площадью. Двумерная упаковка прямоугольников — NP-трудная задача, поэтому результат **близок к оптимальному, но не гарантированно оптимален**.

## Структура проекта

```
src/
  domain/            чистый TypeScript, без React и браузерных API
    types.ts
    validation.ts    проверка складов, коробок, партии
    layout.ts        разметка этажа на ряды и проходы
    packing/
      maxRects.ts     MaxRects-упаковка ряда
      planner.ts      планировщик размещения (мультистарт)
    stats.ts          статистика заполнения
  data/
    seed.ts           демо-данные
    storage.ts        localStorage: версия схемы, безопасный парсинг, откат к сиду
  state/
    useAppStore.ts    состояние приложения и сохранение
  components/         переиспользуемые UI-компоненты (формы, схема этажа)
  pages/
    WarehousesPage.tsx
    BoxTypesPage.tsx
    PlanningPage.tsx
  App.tsx, main.tsx
```

## Ограничения MVP

- Размещение только по плоскости этажа — без штабелирования коробок друг на друга.
- Партия ограничена 300 коробками за раз (валидационная проверка в форме).
- Все размеры — целые сантиметры, вес — в килограммах.
- Нет сервера и многопользовательского режима: данные живут в `localStorage` конкретного браузера.
- Базовая адаптивность вёрстки, без отдельной мобильной версии.
